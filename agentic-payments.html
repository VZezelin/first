x402 path

Apify's documented x402 flow purchases a prepaid API token with USDC on Base, then uses that token as a normal bearer credential against the Apify API. The token is the caller's credential; nothing on this site contains or proxies a Signal Lab owner token.

# After following Apify's x402 guide and receiving a prepaid token:
curl -X POST \
  'https://api.apify.com/v2/actors/ACTOR_ID/run-sync-get-dataset-items' \
  -H "Authorization: Bearer $TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"your":"actor input"}'

Skyfire path

For Skyfire, Apify documents discovering payment requirements with X-APIFY-PAYMENT-PROTOCOL: SKYFIRE, then running an eligible Actor with a skyfire-pay-id token.

# Discover payment requirements for an eligible Actor:
curl -si \
  -H 'X-APIFY-PAYMENT-PROTOCOL: SKYFIRE' \
  'https://api.apify.com/v2/actors/ACTOR_ID/run-sync-get-dataset-items'

# Then run with the payer's Skyfire PAY token:
curl -X POST \
  'https://api.apify.com/v2/actors/ACTOR_ID/run-sync-get-dataset-items' \
  -H 'skyfire-pay-id: YOUR_SKYFIRE_PAY_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{"your":"actor input"}'
